Gate: UNVERIFIED until an attended run across actual local midnight. Controlled clocks and the short 8 October Sleep test do not pass this gate. Do not change Windows system time. Do not start an overnight automation or leave the PC running for this test without the user's approval.

1. Use the isolated installed **DOM.OS Notification Test** application and synthetic profile. Confirm its identity `com.dom.os.notificationtest`, time zone **Europe/London**, current real local date D, notification sound preference on, quiet hours off for this controlled test, DND off and no automatic DND rule interrupting the interval. Record original settings and restore them afterwards.
2. With user approval to keep the PC/app running, create uniquely named Tasks at **D 23:58** and **D+1 00:02**, duration ten minutes. Create an Event spanning **D 23:55–D+1 00:05**. Add a daily Routine start near midnight and an optional Habit reminder at **00:04** through the existing canonical UI. Record the profile UUID, source IDs, planned times and occurrence IDs from read-only diagnostics/ledger; never insert test records directly into SQLite.
3. At **23:57**, start a synthetic linked Work Session. Keep the app running through midnight. Record the previous-day Summary/history, unfinished Tasks and active Work state. Do not mark any Review complete.
4. Observe **23:58** delivery, actual popup and one sound, then the real **00:00** boundary. Dashboard's local day and Now/Up Next must refresh without moving or completing previous-day sources. Inspect the previous-day Summary and intentionally selected historical view: evidence/navigation and drafts must be preserved.
5. At **00:02/00:04**, observe genuine current-day reminders and exact source/civil occurrence identity. Check one durable attempt per standard occurrence, separate recurring-day identities, no replay of old resolved reminders and no sound burst. Verify active Work remains running and linked planned/actual times remain distinct.
6. Stop the Work Session around **00:07**. History/time summaries must split the actual segment at the real profile-local midnight, preserve its original UTC timestamps and add both day portions to the session total without duplication. Previous-day Routine/Habit/Task states must remain genuine: no fake completion/failure, mandatory Review or fabricated records.
7. Repeat the midnight boundary with a user-approved physical Sleep spanning **23:59–00:06** during final release validation. Wake must refresh current day and summaries; relevant missed commitments remain discoverable in one quiet catch-up, completed/obsolete sources do not sound, and a fresh **00:10** reminder proves continued processing. This sleep variant is a separate observation, not implied by active-midnight success.
8. Save real screenshots before/after, UTC and Europe/London wall times, ledger/source snapshots, actual Windows popup/click observation, human sound confirmation and original-setting restoration. Mark each expectation PASS/FAIL/UNVERIFIED with evidence. Failed observations remain gates; API acceptance or clock simulations cannot substitute for physical overnight evidence.

No overnight run was performed during the daytime closure session. Production signing, installation and 6.1.3→6.2 updater acceptance remain separate gates.
